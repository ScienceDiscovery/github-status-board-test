# 增量同步与完整历史

## 功能与数据范围

每个看板仓单独保存同步状态和公开数据。Bot 只提交刷新信号，Actions 使用 API 采集；漏 Webhook、重复触发或 Bot 停机都不改变数据事实来源。定时工作流从仓内断点继续，全部 Webhook 存档仍由 Bot 按原规则保存。

Issue / PR 的开放及关闭记录不设保留条数上限。Actions 保存 run / attempt 的状态、工作流、触发事件、门禁／每日／版本分类、分支、head 仓库、SHA、GitHub 链接与可核验测试指标。版本发布也逐页回填。历史尚未补齐时，页面显示“历史回填中”和已采集数量；列表回填完成不代表所有报告都有可读指标。

完整历史分片是采集器的存储，用于增量汇总与对账；站点不再提供逐条浏览历史的页面，普通页面也不下载历史分片。当前工作列表预览 200 条、近期关闭 100 条、构建预览 100 次、版本预览 30 条；这些是显示窗口，不删除历史分片。汇总以已采集历史及全部开放工作项为基础，CI 使用每个 run 的最后一次 attempt；历史指标汇总另按 attempt 计数。

## 文件和提交

- `.sync/state.json`：源仓、schema、各列表的页码／水位／时间窗口、重试队列、对账进度及错误类别；不含凭据、Webhook 正文或测试日志。
- `.sync/aggregate.json`：可撤销贡献的全量计数，Issue/PR 按状态和日，运行按工作流、阶段和日。
- `.sync/supplements.json`：每日刷新一次的公开运维、测试文件分布和覆盖率信息；`lines.<key>` 为其他[分支线](branch-lines.md)的测试与覆盖率。
- `.sync/coverage.json`：看板读过的覆盖率摘要（不含逐文件列表）及覆盖率产物清单与已见到的最新产物 ID；`.sync/coverage-sources.json` 只保存当前页面在用的摘要的逐文件列表。见下文“只读取没见过的产物”。
- `.sync/tagged.json`：按分支保存的最新标签化测试目录（按标签签名压缩）、各组合最近运行的选择器与结果、标签词表；见[标签化测试](tagged-tests.md)。
- `site/data/history/records/<类型>/<编号段>.json`：完整记录或小型指标。Issue/PR 每 100 个编号一段；run 按稳定 ID 段保存，每个 attempt 独立键。
- `site/data/history/index/`：对应分片的搜索摘要，run 摘要含触发事件、关联 PR、目标分支和 head 仓库，PR 摘要含 head / base 分支（早期索引行缺少时从记录重建一次）；`catalog/` 合并相邻稀疏索引，避免每几个 run 发起一次 HTTP 请求。manifest 给出类型、计数和内容版本。只重写变化分片和对应目录。
- `site/data/snapshot.json`：当前汇总及轻量页面预览。

进度和数据以同一准确 checkout HEAD 为父提交，使用 Git Data API 非强制更新 main。GitHub 限制每小时的内容创建请求数，因此 256 KiB 以下的文件（单次合计不超过 2 MiB）直接放在建树请求里，只有大文件单独上传 blob；一次提交通常只需三到五个写请求。中断或提交冲突不会发布半套进度；重新运行从最新 main 重新取数，幂等 upsert 不重计。`.sync/` 不在 Pages 上传目录，但仓库公开，因此其中所有内容同样必须可公开。禁止写入本机路径、令牌或私有数据。

## 增量、回填与预算

`publish.py --incremental` 从当前 checkout 恢复；首次仅迁移旧快照中已存在的记录／指标，不能把有限旧快照当成完整历史。每轮默认 180 次主要 API／下载调用、480 秒主采集预算；每列表单轮最多 4 页，另有详情批次。到预算即保存本轮已经完成的进度，下轮继续；它限制每轮工作量，不限制长期数据量。公开补充区块每日复用缓存，独立于历史回填。

Issue 按 updated 的 since 水位增量读取；PR 按 updated 倒序读到上一水位，均重叠一小时。历史按创建顺序逐页补齐。每周开始一轮小批量全表对账，修复翻页期间顺序变化、旧 PR 更新及旧构建重跑；对账也有持久游标。旧已完成 run 的重新运行最迟由对账发现；新建运行与已知在途运行优先处理。

Actions 历史按固定 created 时间窗遍历，遇到 GitHub 每次筛选查询 1,000 条的限制，将窗口递归切成不重叠秒区间。极端情况下同一秒仍超过 1,000 条会显式记录 `time_window_saturated` 并保持未完成，不静默丢弃；需再细分到工作流后重试。

重试按类别保存，403、404、限流或暂时故障不能删除已有数据；没有看到对象也不自动当作删除。记录目前长期保留，不同步物理删除。待补详情与失败数在历史页显示。定时任务更新日期相关统计；旧状态修正时先撤销旧贡献，再加入新值。

## 测试指标缓存

报告匹配 run / SHA / attempt，历史 attempt 使用下一次开始时间作为上界，避免借用重跑后的报告。解析键包含 run、attempt、artifact ID、可得 digest、更新时间和 parser version。未变化且已解析的产物复用指标，不再下载；失败和迟到产物继续重试。

报告只在内存下载、解析。公开历史不保存原始 ZIP、日志、截图、trace 或逐用例执行内容；仅保留各层 total / passed / failed / skipped / flaky、可读覆盖率与 GitHub 链接。已有数值不因产物被删除／过期清零。接入前已过期且未采集到的数据保持未知，不用 job success 或测试文件数推断用例通过率。

运行中的 run 每 2 分钟复查，先完成的层的报告不代表整次运行；运行完成时立即读取其余产物。完成的 attempt 的 job 与产物不再变化：报告全部读到即移出复查队列；没有可读报告的，完成后再看一次（防止产物列表延迟）后移出；只有详情读取失败的继续按退避重试，最长一周；长期记录由对账再次检查。解析版本改变且报告仍可读时重算，过期报告保留旧版本指标。当前产物预算为单 ZIP 80 MiB、展开 160 MiB／3,000 条目；超预算明确为不可读取，不清除先前指标。

## 只读取没见过的产物

Actions 产物上传后不再变化，看板已经读过的内容不再下载：

- 覆盖率页的摘要：每个摘要只下载一次，结果记在 `.sync/coverage.json`。产物清单按新到旧分页，读到已见过的产物 ID 即停止，更早的从记录里取；过期产物自动移除，所有分支线都刷新的构建（至少每天一次）还会移除不再入选的摘要和不再显示的逐文件列表。下载失败的摘要不记录，下次重试。
- run 的报告：覆盖率摘要（`node-` / `python-coverage-summary-*`）不再在 run 详情里下载，由覆盖率页通过上面的记录读取；发布了摘要的 run 也不再下载原始覆盖率产物（如 `ut-coverage`）。读过但没有用例数的产物，以及超出大小／展开预算或格式损坏的产物（记为 `unreadable`），把解析键记在 run 记录的 `inspected` 中，复查时不再下载；只有网络、限流等暂时错误会重试。解析版本改变时重新读取，并替换而不是重复其中的覆盖率。
- 测试与覆盖率补充数据刷新失败（例如 API 额度用尽）时保留上一份可用结果，并在下一次构建重试，不用错误区块覆盖。

采集失败时输出一行 JSON：`error`（类别）、`phase`（`collect` / `snapshot` / `publish`）、`status`（HTTP 状态），限流时另有 `limit`（`primary` / `secondary`）与 `reset_at`；不包含 URL、令牌或响应正文。

## 性能与边界

无公开数据变化且日期／完整性未变时复用快照和时间戳，只提交必要进度，不触发 Pages。完整历史保存在稳定分片，首页不下载所有正文或运行指标。增量贡献避免全历史测试报告重解析；旧列表索引仍需扫描以生成部分管理统计，全部开放项仍参与汇总。Git clone 只取当前浅层版本，不取完整提交历史。

Pages 每次部署仍整站上传 site，并非文件级增量部署。GitHub Pages 有站点容量边界；本实现不承诺无限字节容量。数据增长后需观测仓库与站点体积，再决定外置历史存储，不能悄悄改回业务条数截断。

验证入口：`tests/test_incremental.py`。覆盖超旧上限回填、预算重启、权限失败、重开撤销计数、缓存和过期、attempt 隔离及原子提交冲突。
