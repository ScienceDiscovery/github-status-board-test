# 页面与交互

看板只展示已采集的稳定状态，不运行测试。页面依次为：总览、Issue、PR、CI、测试、Coverage、版本验证、运维。配置了[分支线](branch-lines.md)时，CI、测试、Coverage 页首可在默认分支与长期开发分支之间切换，每次只显示一条分支线。旧的“看板”“构建报告”“历史数据”页已移除；看板形式并入 Issue 与 PR 页，历史分片仍作为采集器的存储保留。

## 总览

总览面向“今天要处理什么”，从上到下依次展示以下内容。

**需要处理的问题**，按严重程度排序：

- 主干 CI 连续失败或最近一次失败。
- 每日构建最近一次失败，或超过 36 小时没有运行。
- 最新版本没有提交一致的验证运行，或验证失败。
- 开放 PR 的检查失败、评审超期或存在冲突。
- 其他分支线最近一次 push / 手动运行失败。

CI、PR、Issue 数据不可读取时显示“状态未知”，不会显示为正常。较低优先级的提示（标签化用例从未覆盖、Issue 零回复或陈旧、大量未发布提交、默认分支未保护）折叠在“其他提示”中。

**流水线**（默认分支线）：PR 门禁、主干、每日构建、版本构建四张卡片，给出最近一次运行的结论、时间、工作流和近 30 天成功率。下方是近 14 天的分层图，与 CI 页同一数据，[CI 分层历史](ci-history-lanes.md)有详细说明。

**交付与质量**：

- 开放 PR（评审超期、检查失败、30 天合并）。
- 开放 Issue（7 天新增 / 关闭、陈旧）。
- 主干门禁用例（最近一次各层通过 / 计划数）。
- 整仓行覆盖率。
- 最新版本及其后的未发布提交数。

**版本质量**列出最近三个版本的验证运行结论；**最近动态**列出最近合并的 PR 和新建的 Issue。

## Issue 与 PR

统计信息在上。列表可在“表格”和“看板”之间切换，选择保存在本浏览器。

- **表格**：保留原来的只读列表和筛选。
- **看板**：只显示本页类型的工作项，含最近关闭的；分组、筛选和“等高列”偏好也按类型分别保存。

看板的状态、优先级、迭代、备注和列设置仍只写本浏览器存储，可导入 / 导出，不写回 GitHub。列内容超出高度时各列独立滚动，定时刷新后保留滚动位置。

## 测试与 Coverage

测试页展示：

- 测试文件与最近一次 UT / E2E 用例数；
- [标签化测试](tagged-tests.md)；
- 按层 / 包的测试文件分布，以及按包的测试结构。

逐次运行的明细和覆盖率不在测试页展示。

Coverage 页按语言展示整仓汇总、每日趋势、目录树、路径分组和最近 PR 结果。

目录树按目录逐层展开到单个文件，列出行、分支（Node.js 另有函数）覆盖率和已覆盖 / 总行数：

- 目录的数值是其下所有文件按计数相加，不是百分比平均。
- 只有一个子目录的链会合并为一行，例如 `apps/web/src/`。
- 路径过滤同时作用于目录树和路径分组，过滤时自动展开匹配项。
- 展开状态在定时刷新后保留。

目录树的数据来自源仓覆盖率摘要中的 `sources` 列表，每项为仓库相对路径加该文件自己的 totals。当前值与整仓结果口径一致：以最新完整基线的文件为底，每个主干增量替换它所测分组下的文件；PR 结果不改变主干视图。其他分支线只用自己运行的摘要，见[分支线](branch-lines.md)。摘要没有 `sources` 时，目录树提示暂无逐文件数据，其余视图不受影响。

## 版本验证与运维

版本验证页只把提交 SHA 与版本一致的验证运行关联到版本，并给出 E2E 通过数；没有匹配运行时明确标出，发布成功不代表测试完成。运维页保持原有的分支、社区与贡献信息。

## 验证

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
node .e2e/node_modules/playwright/cli.js test --config test/playwright.config.cjs
```

浏览器用例覆盖：

- 总览的问题排序与数据缺失时显示“状态未知”；
- Issue / PR 的表格 / 看板切换、按类型隔离、本地字段与导入导出；
- 看板列独立滚动与刷新后保留位置；
- 覆盖率目录树的展开、收起与过滤；
- 分支线切换及各线数据互不混合；
- 版本验证关联；
- 窄屏布局。

`tests/test_coverage.py` 验证逐文件数据随基线与增量组合。
